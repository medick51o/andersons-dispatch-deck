## 1. The trigger rule

House first, always. The bench is the exception, and every reach must name which condition fired.
Five legal triggers:

- **T1 · NEW LINEAGE.** The job needs an independent reviewer or an extra vote and every reachable
  house lineage is either implicated in the build or down. Kimi (Moonshot), GLM (Zhipu), and
  Composer (Cursor) are the only lineages the house lacks. This is the bench's main reason to exist.
- **T2 · CONTEXT CLASS.** The artifact doesn't fit a house seat's practical window — whole-repo
  sweep, a full episode transcript, a 500-page spec. Route to a 1M tier (the `claude-opus-5-*` and
  `gpt-5.6-*` 1M rows) — after the lineage check in §5, since those rows are Anthropic/OpenAI blood.
- **T3 · THE EFFORT KNOB.** Well-specified WORKHORSE/FAST work where you want to buy exactly low or
  medium effort. SPINE's lever 4 (reasoning effort per dispatch) is N/A on the house seats and live
  here — the only seat where it exists at all.
- **T4 · LIMP-HOME RESERVE.** A house vendor is rate-limited or down mid-mission and the mission
  would stall. The bench is the spare tank — spent reluctantly, narrated 💸.
- **T5 · SPEED BURST (weak trigger).** A latency-sensitive mechanical pass where Composer 2.5's
  4.7-second answer beats queueing a busy house seat. Legal only for genuine FAST-class work; never
  a habit.

Reaching for the bench is WRONG when:

- **W1 · A house seat clearly clears the bar.** $0 marginal beats any meter. This is the default;
  the bench must *beat* the house seat for the job, not merely tie it.
- **W2 · Curiosity.** "Let's see what GLM 5.2 Max can do" is a benchmark run, not a dispatch.
  Benchmarks get offered to the boss as their own line item, never smuggled into missions.
- **W3 · Same-brain laundering.** Cursor-hosted Claude/GPT/Grok/Gemini is the house's own lineage
  wearing a meter — all of the cost, none of the independence.
- **W4 · `auto` for anything that matters.** Per-call unknown lineage fails closed: it can never
  review, and you cannot learn from a seat you cannot name.
- **W5 · Big job, unknown pool.** Never open a long metered build when the plan card's pool line
  isn't "fresh."

## 2. Suggest vs. summon

The consent line is money, because spend is the irreversibility here. Three bands:

- **SILENT SUMMON — the bench warrant.** Allowed only when ALL hold: (a) the boss has signed a
  standing warrant on `PLAN-CARD.md` naming the class and the exact models (e.g. *"read-only reviews
  on `kimi-k3-high` / `glm-5.2-high`, single call, pre-approved"*); (b) the call is read-only (no
  `always_approve`); (c) one call, bounded prompt; (d) the pool line reads fresh. Even then: 💸
  narrated, routing-ledger line written. This is exactly the operator's Kimi-K3-long-review case —
  pre-permission is what converts it from a purchase into a habit.
- **OFFER FIRST — the default for everything else.** Any build ticket (write-capable = `--yolo` =
  real risk and real spend), any model off the warrant, any multi-call session, any first use of a
  family, any call while the pool line is unknown. The offer is one line: model, why it beats the
  house for THIS job, rough shape. The boss says yes.
- **EXPLICIT RULING.** Anything that could push past the plan pool (§6 makes that impossible at the
  account level; if that cap is ever lifted, this band activates), any council that includes bench
  seats (councils already ask first — the metered seat makes the ask louder), and any bench use
  while posture is SHOESTRING, where the correct answer is almost always no.

The bench inherits the council's consent grammar — offered, never auto-fired — with the warrant as
the single narrow exception, because the boss has already said he wants that exception to exist.

204 rows is fiction within a month. The pool is really ~7 families × effort tiers × `-fast`
variants; the ledger should be **family rows with named, verified members** — 10–15 rows, not 204.

File: `docs/cursor-bench-ledger.md` (Appendix-A class: wiring, not law). Columns:

| Column | Content |
|---|---|
| family / models | e.g. `kimi-k3-{low,high,max}` — a pattern, not three rows |
| seat mark | 🟣 + brain color (`claude-*` rows render 🟠🟣 — banner never lies). *Housekeeping: notation v4.0 retired 🟣 as a meaning; assigning it to the Cursor HOST is an Appendix-A amendment — ⚪⚖️ ruling requested. The brief already uses it, so this answer does too.* |

| context | standard / 1M |
| effort range | low→max; `-fast` variant? (the knob this seat uniquely has) |
| cost shape | cheap / mid / dear — relative only, NEVER prices (the currency rule) |
| verified | date + probe ("answered ping 2026-08-23, 4.7s"). No date = rumor, not a seat |
| best-for | one line, evidence only, append-only like Appendix B |
| never-for | proven failure modes |

Anti-rot mechanics:

1. **Generated, not remembered.** `cursor-agent models` is the source of truth; the ledger is a
   dated cache of it plus field notes. Re-sync on pool diff.
2. **Three update events only:** the models list changes · a run PROVES something (Appendix-B-style
   field note) · the plan lapses (whole ledger → 🪦). No speculative edits.
3. **Unverified rows can't be cast.** Preflight probes before any row is counted — the same law the
   house seats already live under.
4. Keep it separate from Doctrine 6's lineage ledger (track record). This is a menu; that is a
   reputation. Link, don't merge.

## 4. What the bench is genuinely GOOD for

Skeptical answer first: **~85% of the pool is the house's own brains wearing a meter.** The 88
`claude-*` and 83 `gpt-*` rows buy nothing the house doesn't do at $0 marginal — they are W3 traps
with good marketing. If the pool were only the four house families, the correct doctrine would be
"seal it except LIMP HOME." The honest exceptions, by phase:

- **Planning:** narrow. House Claude/Codex plan fine. The one real add is a genuinely different
  PRIOR on a design fork — `kimi-k3-high` or `glm-5.2-max` as a cheap fourth read from a lineage
  that built nothing. (This council, for instance.)
- **Building:** the weakest case — builds are long, write-capable, and meter-hungry. Two narrow
  exceptions: `composer-2.5-fast` for latency-sensitive mechanical edits while house seats are
  busy; `kimi-k2.7-code` as a WORKHORSE builder when the boss deliberately wants a non-house
  lineage on the hammer (a diversity build). Default: NO.
- **Reviewing — the bench's home turf.** `kimi-k3-high` on a long review (the boss's own example):
  efficient, and a REAL new lineage against Claude/GPT/Grok/Gemini builds. `glm-5.2-high` as a
  second cheap independent vote or tie-breaker. And the 1M tiers for whole-repo / whole-episode
  review sweeps no house seat can hold at once — mind lineage: `claude-opus-5-*` 1M may review
  OpenAI/Google/xAI builds, never Claude ones.
- **Post-project (docs, retros, sweeps):** the 1M tiers again — a retro over an entire episode
  folder is exactly their shape. `composer-2.5-fast` for fast extraction passes. House Gemini
  already does cheap sweeps at $0, so the bench only wins when the artifact is too big for it.

## 5. Lineage safety

Three layers, no new law — Part VI's effective-model preflight with teeth:

1. **The ledger's lineage column is normative.** Rule text: *"Lineage is a property of the model
   ID's family prefix, never of the seat it arrived through. `claude-opus-5-high` on 🟣 is Anthropic
   blood on a Cursor host — 🟠🟣 — and may never review Claude work."*
2. **The banner already knows how.** Borrowed-brain notation (🟠🟢) extends to 🟣 hosts: brain color
   + host color, always both. The wrapper footer already prints the exact model and token counts per
   call — that line goes into the routing ledger verbatim, so the receipt and the claim cannot drift.
3. **The review ticket states the pair.** One checklist line: `builder lineage: X · reviewer
   lineage: Y`. X = Y → the review is SOLO-VENDOR DEGRADED, declared as such, never counted
   cross-vendor. `auto` and any model whose family can't be mapped = UNKNOWN LINEAGE → fails
   closed, never a reviewer.

## 6. The budget rule

Enforceable means a wall, not a promise. In order of actual enforcement power:

- **B1 · The account is the wall.** On-demand / usage-based billing OFF at the Cursor account
  (spend limit $0). Then the worst case is not a bill — it is the seat going dark mid-mission, which
  the method already handles (shed the bench first, LIMP HOME back to the house). Every rule below
  is narration; this one is physics. The boss sets it once; the orchestrator never touches it.
- **B2 · First shed, never fanned.** The bench is the first seat dropped in any crunch and never
  runs in parallel. The wrapper is already serial (one request at a time, no cancellation) — keep
  it that way; do not "fix" that.
- **B3 · 💸 on every line.** The mark is mandatory, and the wrapper's token footer goes into the
  routing ledger. The mission report's cost note is non-optional whenever a bench call ran.
- **B4 · Pool state is a plan-card line, boss-declared.** The orchestrator cannot meter the pool
  (the currency rule). The card carries `cursor pool: fresh / low / spent / unknown`; unknown +
  anything big = offer first. When a call errors with pool exhaustion, the line flips to spent and
  every warrant suspends itself.
- **B5 · Warrants die with the plan.** Renewal = re-run the bench preflight and re-sign warrants.
  Lapse = ledger 🪦, warrants void, no zombie permissions. The seat disappears the day the plan
  lapses — the doctrine should disappear with it, audibly, not silently rot.

## 7. What I would REFUSE to build

**The auto-router.** A per-task picker over 204 models (or leaning on the pool's `auto` entry) is
the one artifact that looks like the whole point of this exercise and is actually its undoing. It
spends money to spare the orchestrator a routing decision — the exact judgment the method exists to
exercise. It optimizes a number the shop admits it cannot observe (the currency rule: no real-time
metering). Worst, it makes lineage per-call unknowable, which silently poisons every future review
the seat touches. A 204-model menu invites the slot machine; the slot machine is not a seat.

Honorable refusals: per-model emoji for 204 models (the legend is a status light, not a sticker
book — family marks suffice), and a benchmark farm to "map the pool" (an unasked fleet burning the
plan pool for curiosity — W2 in a lab coat).
